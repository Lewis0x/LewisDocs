# 扩展 Claude Code

> 了解何时使用 CLAUDE.md、技能、子代理、钩子、MCP 和插件。

Claude Code 将推理代码的模型与用于文件操作、搜索、执行和网络访问的 [内置工具](/docs/en/how-claude-code-works#tools) 相结合。内置工具涵盖了大部分编码任务。本指南介绍扩展层：你添加的用于自定义 Claude 所知信息、将其连接到外部服务以及自动化工作流的功能。

<Note>
  关于核心智能体循环的工作原理，请参见 [How Claude Code works](/docs/en/how-claude-code-works)。
</Note>

**刚接触 Claude Code？** 为了解项目约定，请从 [CLAUDE.md](/docs/en/memory) 开始，然后 [在出现特定触发条件时](#build-your-setup-over-time) 添加其他扩展。

## 概述

扩展程序插入到智能体循环的不同部分：

* **[CLAUDE.md](/docs/en/memory)** 添加 Claude 在每次会话中看到的持久上下文
* **[技能](/docs/en/skills)** 添加可重用的知识和可调用的工作流
* **[代码智能](/docs/en/tools-reference#lsp-tool-behavior)** 将 Claude 连接到语言服务器，以进行符号级导航和实时类型错误检查
* **[MCP](/docs/en/mcp)** 将 Claude 连接到外部服务和工具
* **[子代理](/docs/en/sub-agents)** 在隔离的上下文中运行各自的循环，并返回摘要
* **[智能体团队](/docs/en/agent-teams)** 通过共享任务和点对点消息传递协调多个独立的会话
* **[钩子](/docs/en/hooks-guide)** 在生命周期事件触发时运行，可以执行脚本、HTTP 请求、提示词或子代理
* **[插件](/docs/en/plugins)** 和 **[市场](/docs/en/plugin-marketplaces)** 对这些功能进行打包和分发

[技能](/docs/en/skills) 是最灵活的扩展。技能是一个包含知识、工作流或说明的 Markdown 文件。你可以使用类似 `/deploy` 的命令调用技能，或者 Claude 可以在相关时自动加载它们。技能可以在你当前的对话中运行，也可以通过子代理在隔离的上下文中运行。

## 根据您的目标匹配功能

功能范围从 Claude 在每次会话中都能看到的常驻上下文，到您或 Claude 可以调用的按需功能，再到在特定事件下运行的后台自动化。下表展示了可用功能以及每种功能适用的场景。

| 功能                                                            | 作用                                                          | 何时使用                                                                        | 示例                                                                           |
| -------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **CLAUDE.md**                                                  | 每次对话加载的持久上下文                                      | 项目约定、“始终执行 X”的规则                                                    | “使用 pnpm，而不是 npm。提交前运行测试。”                                       |
| **技能**                                                       | Claude 可以使用的指令、知识和工作流                           | 可重用的内容、参考文档、可重复的任务                                            | `/deploy` 运行您的部署清单；带有端点模式的 API 文档技能 |
| **子代理**                                                     | 返回汇总结果的隔离执行上下文                                  | 上下文隔离、并行任务、专用工作者                                                | 读取多个文件但仅返回关键发现的研究任务                                          |
| **[代理团队](/docs/en/agent-teams)**                               | 协调多个独立的 Claude Code 会话                      | 并行研究、新功能开发、使用竞争假设进行调试                                      | 生成审查者以同时检查安全性、性能和测试                                          |
| **[代码智能](/docs/en/tools-reference#lsp-tool-behavior)**   | 语言服务器导航和诊断                                          | 强类型语言、grep 缓慢或不精确的大型代码库                                        | 跳转到符号的定义，而不是阅读整个文件                                            |
| **MCP**                                                        | 连接到外部服务                                                | 外部数据或操作                                                                  | 查询您的数据库、发布到 Slack、控制浏览器                                        |
| **钩子**                                                       | 由事件触发的脚本、HTTP 请求、提示或子代理                     | 必须在每个匹配事件上运行的自动化                                                | 每次文件编辑后运行 ESLint                                                      |
| **[产物](/docs/en/artifacts)**                                    | 将会话输出发布为私密的交互式网页                              | 您希望以可视化方式查看或分享而不是作为终端文本的输出                             | 随着 Claude 的调查而更新的故障时间线                                            |

**[插件](/docs/en/plugins)** 是打包层。插件将技能、钩子、子代理和 MCP 服务器捆绑到一个可安装单元中。插件技能具有命名空间（如 `/my-plugin:review`），因此多个插件可以共存。当您希望在多个存储库中重用相同的设置，或通过 **[市场](/docs/en/plugin-marketplaces)** 分发给他人时，请使用插件。

### 逐步构建你的设置

你不需要一开始就配置好所有内容。每个功能都有一个可识别的触发条件，大多数团队大致按以下顺序添加它们：

| 触发条件                                                                          | 添加                                                                                            |
| :------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------- |
| Claude 两次弄错同一个约定或命令                                  | 将其添加到 [CLAUDE.md](/docs/en/memory)                                                              |
| 你持续输入相同的提示来开始任务                                  | 将其保存为用户可调用的 [技能](/docs/en/skills)                                                |
| 你第三次将相同的行动指南或多步流程粘贴到聊天中 | 将其捕获为 [技能](/docs/en/skills)                                                            |
| 你不断从 Claude 看不到的浏览器标签页中复制数据                        | 将该系统连接为 [MCP 服务器](/docs/en/mcp)                                                |
| Claude 读取许多文件以查找符号定义或使用的位置                | 为你的语言安装 [代码智能插件](/docs/en/discover-plugins#code-intelligence) |
| 一个次要任务用你不会再参考的输出淹没了你的对话       | 通过 [子代理](/docs/en/sub-agents) 路由它                                                  |
| 你希望某件事每次无需询问就会发生                           | 编写一个 [钩子](/docs/en/hooks-guide)                                                                |
| 第二个代码库需要相同的设置                                         | 将其打包为 [插件](/docs/en/plugins)                                                          |

相同的触发条件会告诉你何时更新现有内容。重复的错误或反复出现的审查评论是一次 CLAUDE.md 编辑，而不是聊天中的一次性纠正。你不断手动微调的工作流是一个需要再次修订的技能。

### 比较相似功能

有些功能可能看起来很相似。有关如何在它们之间做出选择的更深入演练，请参阅博客上的 [Steering Claude Code: 何时使用 CLAUDE.md, 技能、钩子和子智能体](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)。以下是区分它们的方法。

<Tabs>
  <Tab title="技能与子智能体">
    技能和子智能体解决不同的问题：

    * **技能** 是您可以加载到任何上下文中的可重用内容
    * **子智能体** 是独立于您的主对话运行的隔离工作进程

    | 方面                                            | 技能                                            | 子智能体                                                            |
    | ----------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------- |
    | **它是什么**                                      | 可重用的指令、知识或工作流                    | 具有自己上下文的隔离工作进程                                        |
    | **主要优势**                                      | 跨上下文共享内容                              | 上下文隔离。工作单独进行，仅返回摘要                                |
    | **[上下文窗口](/docs/en/context-window) 影响** | 添加到您的主窗口                             | 使用单独的窗口，具有自己的输入和输出 token                        |
    | **最适合**                                        | 参考资料、可调用的工作流                      | 读取许多文件的任务、并行工作、专门的工作进程                          |

    **技能可以是参考或操作。** 参考技能提供 Claude 在您整个会话中使用的知识（例如您的 API 风格指南）。操作技能告诉 Claude 执行特定的操作（例如运行您部署工作流的 `/deploy`）。

**使用子代理（subagent）** 当您需要上下文隔离或上下文窗口即将占满时。子代理可能会读取数十个文件或执行大量搜索，但您的主对话只会收到一份摘要。由于子代理的工作不会消耗您的主上下文，因此当您不需要中间过程保持可见时，这也非常有用。自定义子代理可以拥有自己的指令并预加载技能。

    **它们可以结合使用。** 子代理可以预加载特定的技能（`skills:` 字段）。技能可以使用 `context: fork` 在隔离的上下文中运行。详情请参见 [Skills](/docs/en/skills)。
  </Tab>

  <Tab title="CLAUDE.md vs Skill">
    两者都存储指令，但它们的加载方式不同，且用途各异。

    | 方面                      | CLAUDE.md                    | 技能                                     |
    | ------------------------- | ---------------------------- | --------------------------------------- |
    | **加载方式**              | 每次会话自动加载             | 按需加载                                 |
    | **能否包含文件**          | 是，通过 `@path` 导入       | 是，通过 `@path` 导入               |
    | **能否触发工作流**        | 否                           | 是，通过 `/<name>`                     |
    | **最适用于**              | “总是执行 X”规则             | 参考资料、可调用的工作流                 |

    **将其放入 CLAUDE.md** 如果 Claude 应当始终了解它：编码规范、构建命令、项目结构、“绝不执行 X”规则。

    **将其放入技能中** 如果它是 Claude 偶尔需要的参考资料（API 文档、风格指南），或者是您通过 `/<name>` 触发的工作流（部署、审查、发布）。

    **经验法则：** 将 CLAUDE.md 保持在 200 行以内。如果它正在增长，请将参考内容移动到技能或拆分为 [`.claude/rules/`](/docs/en/memory#organize-rules-with-claude/rules/) 文件。
  </Tab>

  <Tab title="CLAUDE.md vs 规则 vs 技能">
    这三者都存储指令，但它们的加载方式不同：

    | 方面         | CLAUDE.md                           | `.claude/rules/`                                   | 技能                                      |
    | ------------ | ----------------------------------- | -------------------------------------------------- | ---------------------------------------- |
    | **加载**    | 每次会话                             | 每次会话，或在打开匹配文件时                   | 按需，当被调用或相关时                    |
    | **范围**    | 整个项目                             | 可以限定在文件路径范围                           | 特定于任务                              |
    | **最适用于** | 核心约定和构建命令                   | 特定语言或特定目录的指南                         | 参考资料、可重复的工作流                   |

    **使用 CLAUDE.md** 来提供每次会话所需的说明：构建命令、测试约定、项目架构。

    **使用规则**来保持 CLAUDE.md 聚焦。带有 [`paths` 前置数据 ](/docs/en/memory#path-specific-rules) 的规则仅在 Claude 处理匹配文件时加载，从而节省上下文。

    **使用技能**来提供 Claude 仅偶尔需要的内容，例如您通过 `/<name>` 触发的 API 文档或部署清单。
  </Tab>

  <Tab title="子代理 vs 代理团队">
    两者都可以并行工作，但它们的架构不同：

    * **子代理**在您的会话内部运行，并将结果报告回您的主上下文
    * **代理团队**是独立的 Claude Code 会话，它们之间可以相互通信

    | 方面              | 子代理                                           | 代理团队                                            |
    | ----------------- | ------------------------------------------------ | --------------------------------------------------- |
    | **上下文**        | 拥有独立上下文窗口；结果返回给调用者            | 拥有独立上下文窗口；完全独立                       |
    | **通信**          | 仅向主代理报告结果                               | 团队成员之间直接互相发送消息                         |
    | **协调**          | 由主代理管理所有工作                             | 通过共享任务列表进行自我协调                         |
    | **最适用于**      | 仅关注结果的专注任务                             | 需要讨论和协作的复杂工作                             |
    | **Token 消耗**    | 较低：结果摘要返回至主上下文                     | 较高：每个队友都是一个独立的 Claude 实例            |

    **使用子代理**当您需要快速、专注的执行者时：研究问题、验证声明、审查文件。子代理完成工作并返回摘要。您的主对话保持简洁。

    **使用代理团队**当队友需要分享发现、相互质疑并独立协调时。代理团队最适用于具有竞争假设的研究、并行代码审查，以及每个队友各自负责一部分的新功能开发。

    **过渡点：**如果您正在运行并行子代理但达到了上下文限制，或者如果您的子代理需要相互通信，那么代理团队就是顺理成章的下一步。

    <Note>
      代理团队是实验性功能，默认禁用。有关设置和当前限制，请参见 [代理团队](/docs/en/agent-teams)。
    </Note>
  </Tab>

  <Tab title="MCP vs 技能">
    MCP 将 Claude 连接到外部服务。技能扩展了 Claude 所知道的知识，包括如何有效地使用这些服务。

    | 方面         | MCP                                                  | 技能                                                   |
    | -------------- | ---------------------------------------------------- | ------------------------------------------------------- |
    | **它是什么** | 用于连接外部服务的协议         | 知识、工作流和参考材料            |
    | **提供内容**   | 工具和数据访问                                | 知识、工作流、参考材料                |
    | **示例**   | Slack 集成、数据库查询、浏览器控制 | 代码审查清单、部署工作流、API 样式指南 |

    它们解决不同的问题，并且可以很好地协同工作：

    **MCP** 为 Claude 提供专用于外部系统的工具，连接和身份验证由服务器处理。

    **技能** 为 Claude 提供有关如何有效使用这些工具的知识，以及你可以使用 `/<name>` 触发的工作流。一个技能可能包含你团队的数据库架构和查询模式，或者一个带有你团队消息格式规则的 `/post-to-slack` 工作流。

    示例：一个 MCP 服务器将 Claude 连接到你的数据库。一个技能则教会 Claude 你的数据模型、常见查询模式，以及针对不同任务应使用哪些表。
  </Tab>

  <Tab title="Hook 与 Skill 的区别">
    钩子在生命周期事件发生时触发；技能则被加载到上下文中供 Claude 应用。

    | 方面           | Hook                                                                              | 技能                                                                 |
    | ---------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
    | **运行内容**         | Shell 命令、HTTP 请求、LLM 提示词或子代理                            | Claude 阅读并遵循的指令                                 |
    | **触发条件** | [生命周期事件](/docs/en/hooks#hook-events) 如 `PostToolUse` 或 `SessionStart` | 你输入 `/<name>`，或 Claude 将描述与你的任务匹配 |
    | **确定性**  | 总是在其事件发生时触发；触发是有保证的                              | Claude 解释指令；结果可能有所不同                  |
    | **上下文消耗** | 零（除非 Hook 返回输出）                                               | 每次会话加载描述；使用时加载全部内容          |
    | **最适合**     | 编辑后进行 Lint 检查、阻止不安全的命令、日志记录、通知             | 需要推理的工作流、参考材料、多步骤任务   |

    **使用 Hook** 当动作必须每次以相同方式发生且不需要 Claude 思考时。例如：保存时格式化、拒绝 `rm -rf /`、在会话结束时发送 Slack 消息。

    **使用技能** 当 Claude 应该决定如何应用这些步骤，或者当内容是知识而不是脚本时。例如：一个 `/release` 清单、你的 API 样式指南、一个调试手册。

    **将防护机制放入 Hook 中。** 在 `.env` 或技能中类似“永远不要编辑 CLAUDE.md”的指令只是一种请求，而不是保证。一个阻止该编辑的 `PreToolUse` Hook 才是强制执行。如果一条规则必须每次都成立，请将其设为 Hook，而不是提示词指令。

    **Hook 的输出会进入上下文。** 一个运行你的 linter 的 `PostToolUse` Hook 会将结果作为文本反馈给 Claude 阅读；而一个 `/fix-lint` 技能则告诉 Claude 如何解决这些问题。
  </Tab>
</Tabs>

### 理解功能如何分层

功能可以在多个级别进行定义：用户级、项目级、通过插件或通过托管策略。您还可以在子目录中嵌套 CLAUDE.md 文件，或将技能放置在 monorepo 的特定包中。当同一功能存在于多个级别时，它们的分层方式如下：

* **CLAUDE.md 文件**是累加的：所有级别同时向 Claude 的上下文提供内容。来自您的工作目录及其上级目录的文件在启动时加载；子目录在您工作时加载。当指令发生冲突时，Claude 会酌情进行协调，通常更具体的指令会优先。参见 [CLAUDE.md 文件如何加载](/docs/en/memory#how-claude-md-files-load)。
* **技能和子智能体**按名称覆盖：当多个级别存在相同名称时，将根据优先级决定哪个定义生效（对于技能：托管 > 用户 > 项目；对于子智能体：托管 > CLI 标志 > 项目 > 用户 > 插件）。插件技能会被添加 [命名空间](/docs/en/plugins#add-skills-to-your-plugin) 以避免冲突。参见 [技能发现](/docs/en/skills#where-skills-live) 和 [子智能体作用域](/docs/en/sub-agents#choose-the-subagent-scope)。
* **MCP 服务器**按名称覆盖：本地 > 项目 > 用户。参见 [MCP 作用域](/docs/en/mcp#scope-hierarchy-and-precedence)。
* **钩子**进行合并：无论来源如何，所有已注册的钩子都会在其匹配的事件发生时触发。参见 [钩子](/docs/en/hooks)。

### 组合功能

每个扩展解决不同的问题：CLAUDE.md 处理常驻上下文，技能处理按需知识和工作流，MCP 处理外部连接，子智能体处理隔离，钩子处理自动化。实际的设置会根据您的工作流将它们组合起来。

例如，您可以将 CLAUDE.md 用于项目规范，将技能用于您的部署工作流，用 MCP 连接到您的数据库，以及用一个钩子在每次编辑后运行 lint。每个功能都处理它最擅长的方面。

| 模式                | 工作方式                                                                     | 示例                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **技能 + MCP**        | MCP 提供连接；技能教会 Claude 如何善用它           | MCP 连接到您的数据库，技能记录您的架构和查询模式                   |
| **技能 + 子智能体**   | 技能生成子智能体以进行并行工作                                       | `/audit` 技能启动安全、性能和风格子智能体，它们在隔离的上下文中工作 |
| **CLAUDE.md + 技能** | CLAUDE.md 保存常驻规则；技能保存按需加载的参考材料 | CLAUDE.md 说“遵循我们的 API 规范”，而技能包含完整的 API 风格指南            |
| **钩子 + MCP**         | 钩子通过 MCP 触发外部操作                                     | 编辑后钩子在 Claude 修改关键文件时发送 Slack 通知                     |

## 理解上下文成本

您添加的每个功能都会消耗 Claude 的一些上下文。过多的上下文会填满您的上下文窗口，但也会增加噪音，使 Claude 的效率降低；技能可能无法正确触发，或者 Claude 可能会忘记您的规范。了解这些权衡有助于您构建有效的设置。有关这些功能在运行会话中如何组合的交互式视图，请参见 [探索上下文窗口](/docs/en/context-window)。

### 按功能划分的上下文成本

每个功能都有不同的加载策略和上下文成本：

| 功能               | 何时加载                  | 加载内容                                          | 上下文成本                                 |
| --------------------- | ------------------------------ | --------------------------------------------------- | -------------------------------------------- |
| **CLAUDE.md**         | 会话开始                  | 完整内容                                        | 每次请求                                |
| **技能**            | 会话开始 + 使用时      | 开始时加载描述，使用时加载完整内容       | 低（每次请求加载描述）\*           |
| **MCP 服务器**       | 会话开始                  | 工具名称；按需提供完整架构                  | 使用工具前成本较低                     |
| **代码智能** | 文件编辑后及按需 | 编辑后的诊断；查找时的符号位置 | 低；减少其他地方的文件读取            |
| **子代理**         | 生成时                   | 带有指定技能的全新上下文                 | 与主会话隔离                   |
| **钩子**             | 触发时                     | 无（外部运行）                           | 零，除非钩子返回额外的上下文 |

\*默认情况下，技能描述在会话开始时加载，以便 Claude 决定何时使用它们。在技能的 frontmatter 中设置 `disable-model-invocation: true` 可以将其对 Claude 完全隐藏，直到您手动调用它。这将您仅自行触发的技能的上下文成本降低为零。对于您未编写的技能，请在设置中设置 [`skillOverrides`](/docs/en/skills#override-skill-visibility-from-settings) 来实现相同效果，而无需编辑其文件。

### 了解功能如何加载

每个功能在会话的不同阶段加载。下面的选项卡解释了每个功能何时加载以及哪些内容会进入上下文。

<img src="https://mintcdn.com/claude-code/ikqp3_70mqIahteV/images/context-loading.svg?fit=max&auto=format&n=ikqp3_70mqIahteV&q=85&s=aab139e750494a237ae2e0c8f9139b0a" alt="上下文加载：CLAUDE.md 在会话开始时加载并保留在每次请求中。MCP 工具名称在开始时加载，完整架构推迟到使用时加载。技能在开始时加载描述，调用时加载完整内容。子代理获取隔离的上下文。钩子在外部运行。" width="720" height="382" data-path="images/context-loading.svg" />

<Tabs>
  <Tab title="CLAUDE.md">
    **何时：** 会话开始

    **加载内容：** 所有 CLAUDE.md 文件的完整内容（托管、用户和项目级别）。

    **继承：** Claude 从您的工作目录向上读取到根目录的 CLAUDE.md 文件，并在访问这些文件时发现子目录中的嵌套文件。详情请参见 [如何加载 CLAUDE.md 文件](/docs/en/memory#how-claude-md-files-load)。

    <Tip>将 CLAUDE.md 保持在 200 行以内。将参考材料移至按需加载的技能中。</Tip>
  </Tab>

  <Tab title="技能">
    技能是 Claude 工具包中的额外功能。它们可以是参考材料（如 API 样式指南），也可以是您使用 `/<name>` 触发的可调用工作流（如 `/deploy`）。Claude Code 包含 [捆绑技能](/docs/en/commands)，例如 `/code-review`、`/batch` 和 `/debug`，它们开箱即用。您也可以创建自己的技能。Claude 会在合适的时候使用技能，或者您可以直接调用它们。

    **何时：** 取决于技能的配置。默认情况下，描述在会话开始时加载，完整内容在使用时加载。对于仅用户技能 (`disable-model-invocation: true`)，在您调用之前不会加载任何内容。

    **加载内容：** 对于模型可调用的技能，Claude 会在每次请求中看到名称和描述。当您使用 `/<name>` 调用技能或 Claude 自动加载技能时，完整内容将加载到您的对话中。

    **Claude 如何选择技能：** Claude 会将您的任务与技能描述进行匹配，以决定哪些是相关的。如果描述模糊或重叠，Claude 可能会加载错误的技能，或者漏掉有用的技能。要让 Claude 使用特定技能，请使用 `/<name>` 调用它。带有 `disable-model-invocation: true` 的技能在您调用它们之前对 Claude 是不可见的。

    **上下文成本：** 在使用前很低。仅限用户的技能在被调用前成本为零。

    **在子代理中：** 技能在子代理中的工作方式不同。子代理的 `skills` 字段中列出的技能不会按需加载，而是在启动时完全预加载到其上下文中。子代理仍然可以通过 Skill 工具发现并调用未列出的项目、用户和插件技能。

    <Tip>对于有副作用的技能，请使用 `disable-model-invocation: true`。这样可以节省上下文并确保只有您才能触发它们。</Tip>
  </Tab>

  <Tab title="MCP 服务器">
    **何时：** 会话开始时。

    **加载什么：** 来自已连接服务器的工具名称。完整的 JSON 架构会延迟加载，直到 Claude 需要特定工具。

    **上下文成本：** [工具搜索](/docs/en/mcp#scale-with-mcp-tool-search) 默认开启，因此空闲的 MCP 工具消耗最少的上下文。

    <Tip>运行 `/mcp` 以查看每个服务器的连接状态和令牌成本。如果它们断开，Claude Code [自动重新连接到远程服务器](/docs/en/mcp#automatic-reconnection)，并且您可以断开未使用的服务器。</Tip>
  </Tab>

  <Tab title="代码智能">
    **何时：** 在文件编辑后，以及 Claude 浏览代码时按需加载。

    **加载什么：** 每次文件编辑后的类型错误和警告。当 Claude 查找符号时的定义、引用和类型信息。

    **上下文成本：** 低。符号查找通常取代广泛的文件读取，因此净上下文使用量可能会下降。

    <Tip>在您为您的语言安装 [代码智能插件](/docs/en/discover-plugins#code-intelligence) 之前，LSP 工具处于未激活状态。</Tip>
  </Tab>

  <Tab title="子代理">
    **何时：** 按需，当您或 Claude 为某个任务生成一个子代理时。

    **加载什么：** 全新的、隔离的上下文，包含：

    * 代理自身的系统提示，而不是完整的 Claude Code 系统提示
    * 代理的 `skills:` 字段中列出的技能的完整内容
    * CLAUDE.md 和 git 状态，除了内置的 Explore 和 Plan 代理 [省略两者](/docs/en/sub-agents#what-loads-at-startup)
    * 主导代理在提示中传递的任何上下文

    **上下文成本：** 与主会话隔离。子代理不继承您的对话历史或调用的技能。

    <Tip>将子代理用于不需要完整对话上下文的工作。它们的隔离性可防止主会话臃肿。</Tip>
  </Tab>

  <Tab title="钩子">
    **何时：** 触发时。钩子在特定的生命周期事件（如工具执行、会话边界、提示提交、权限请求和压缩）时触发。完整列表请参见 [钩子](/docs/en/hooks)。

    **加载什么：** 默认不加载。钩子在主对话之外执行。

    **上下文成本：** 为零，除非钩子返回作为消息添加到您对话中的输出。

    <Tip>钩子非常适合不需要影响 Claude 上下文的副作用（如代码检查、日志记录）。</Tip>
  </Tab>
</Tabs>
