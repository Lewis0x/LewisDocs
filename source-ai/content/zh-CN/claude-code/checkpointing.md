# 检查点

> 跟踪、回退并总结 Claude 的编辑与对话，以管理会话状态。

Claude Code 会在你工作时自动跟踪 Claude 对文件的编辑，让你能够在任何内容偏离预期时快速撤销更改并回退到先前状态。

## 检查点的工作方式

在你与 Claude 协作时，检查点功能会在每条用户提示词之前自动捕获代码状态。这张安全网让你可以放心开展目标大胆、范围广泛的任务，因为你始终能够返回先前的代码状态。

### 自动跟踪

Claude Code 会跟踪其文件编辑工具所做的所有更改：

* 每条用户提示词都会创建一个新检查点
* Claude Code 会保留会话中最近 100 个检查点的文件快照。丢弃较早的检查点时，会删除没有任何剩余检查点引用的快照文件，但每个文件的第一个快照除外；VS Code 扩展会将它用作会话差异的基线。{/* min-version: 2.1.208 */}在 v2.1.208 之前，这些已被取代的快照文件会一直留在磁盘上，直到会话被清理。
* 检查点与对话一起保存，因此恢复的会话仍可通过 `/rewind` 回退到这些检查点
* 30 天后随会话一起自动清理，可通过 [`cleanupPeriodDays`](/docs/en/settings#available-settings) 配置

### 回退与总结

运行 `/rewind`，或在提示词输入为空时连按两次 `Esc`，以打开回退菜单。

<Note>
  如果提示词输入中包含文本，连按两次 `Esc` 会清除文本，而不是打开菜单。清除的文本会保存到输入历史记录中，因此在回退菜单中操作完成后，按 `Up` 即可调回该文本。
</Note>

回退菜单会列出你在会话期间发送的每条提示词。选择要操作的时间点，然后选择一项操作：

* **恢复代码和对话**：将代码和对话都还原到该时间点
* **恢复对话**：回退到该消息，同时保留当前代码
* **恢复代码**：还原文件更改，同时保留对话
* **从此处开始总结**：将从该时间点起的对话压缩为摘要，从而释放上下文窗口空间
* **总结到此处**：将该时间点之前的对话压缩为摘要，同时完整保留之后的消息
* **算了**：不做任何更改，返回消息列表

两个代码恢复选项仅在所选检查点包含可还原的已跟踪文件更改时显示。如果该时间点之后没有捕获到文件编辑，菜单只会提供**恢复对话**、总结选项和**算了**。

恢复对话或选择“从此处开始总结”后，所选消息的原始提示词会恢复到输入字段中，以便你重新发送或编辑它。

选择“总结到此处”后，你会停留在对话末尾，输入框为空。无论使用哪种总结选项，对话中被压缩消息所在的位置都会出现**已总结的对话**标记。

#### 回退到已清除对话之前

如果你此前在同一个 Claude Code 进程中运行过 `/clear`，回退菜单会在列表顶部额外显示一个标为 `/resume <session-id> (previous session)` 的条目。选择它可恢复运行 `/clear` 前处于活动状态的对话。该条目会一直可用，直到你退出 Claude Code 或恢复另一个会话，并且要求 Claude Code v2.1.191 或更高版本。在更早的版本中，请改为运行 `/resume`，然后从列表中选择先前的会话。

#### 恢复与总结的区别

恢复选项会还原状态：撤销代码更改、对话历史记录或两者。总结选项会将对话的一部分压缩为 AI 生成的摘要，而不会更改磁盘上的文件：

* **从此处开始总结**：所选消息之前的消息保持完整。所选消息及其之后的所有内容会替换为摘要。需要舍弃一段支线讨论、同时完整保留早期上下文时，请使用此选项。
* **总结到此处**：所选消息之前的消息会替换为摘要。所选消息及其之后的所有内容保持完整，而你仍停留在对话末尾。需要压缩早期设置讨论、同时完整保留近期工作时，请使用此选项。

两种情况下，原始消息都会保留在会话记录中，因此 Claude 可以在需要时引用其中的细节。若要引导摘要的侧重点，请使用方向键突出显示一个**总结**选项，并在该行显示 **add context (optional)** 的位置直接输入说明，然后按 `Enter` 进行总结；使用对应数字键选择选项则会立即总结，不附加说明。这与 `/compact` 类似，但目标范围更精确：你无需总结整个对话，而是选择要压缩所选消息哪一侧的内容。

<Note>
  总结会让你留在同一个会话中，并压缩上下文。如果你想在完整保留原始会话的同时分支出去尝试不同方法，请改用 [`/branch`](/docs/en/sessions#branch-a-session) 或 `claude --continue --fork-session`。
</Note>

## 常见使用场景

检查点在以下情况下尤其有用：

* **探索替代方案**：尝试不同的实现方法，同时不丢失起点
* **从错误中恢复**：快速撤销引入错误或破坏功能的更改
* **迭代功能**：尝试各种变体，并确信可以还原到可用状态
* **释放上下文空间**：从中途开始总结冗长的调试会话，同时完整保留最初的说明

## 限制

### 不跟踪 Bash 命令所做的更改

检查点不会跟踪 Bash 命令修改的文件。例如，如果 Claude Code 运行：

```bash theme={null}
rm file.txt
mv old.txt new.txt
cp source.txt dest.txt
```

这些文件修改无法通过回退来撤销。只有 Claude 的文件编辑工具直接进行的文件编辑会被跟踪。

### 不恢复子代理的编辑

除非是以前台方式运行的[带有 `context: fork` 的技能](/docs/en/skills#run-skills-in-a-subagent)，否则[子代理](/docs/en/sub-agents)所应用的编辑会落在会话检查点之外，因此回退不会恢复这些编辑，即使子代理使用的是 Claude 的文件编辑工具。这包括后台运行的 [`/code-review --fix`](/docs/en/code-review)，以及任何在后台运行的分叉技能。请使用 Git 还原这些编辑。前台分叉会在你自己的轮次中编辑工作树，因此回退会像往常一样恢复其编辑。{/* min-version: 2.1.218 */}分叉技能默认在后台运行；在其 frontmatter 中设置 `background: false` 可使其在前台运行，此时调用它的轮次会等待结果。在 v2.1.218 之前，分叉技能始终在前台运行。

### 不跟踪外部更改

检查点只跟踪当前会话内编辑过的文件。你在 Claude Code 外部对文件进行的手动更改，以及其他并发会话所做的编辑通常不会被捕获，除非这些更改恰好修改了与当前会话相同的文件。

### 不恢复符号链接和硬链接路径

检查点不会回退符号链接或硬链接文件。当你从 `/rewind` 菜单中选择**恢复代码**或**恢复代码和对话**时，Claude Code 会跳过任何属于符号链接或硬链接的已跟踪路径，并显示 `Restored the code, but skipped N files` 警告。被跳过的文件会保留当前内容。若要撤销会话对其中某个文件所做的更改，请让 Claude 反向执行该编辑，或自行编辑该文件。点文件管理器通过符号链接放入项目中的配置文件，以及 pnpm 通过硬链接放置的文件，都属于此类别。

若要查看恢复操作跳过了哪些路径，请在恢复前使用 `/debug` 开启调试日志：`~/.claude/debug/<session-id>.txt` 中的调试日志会列出每个跳过的路径。有关所有跳过原因及恢复步骤，请参阅[错误参考中的“已恢复代码但跳过文件”条目](/docs/en/errors#restored-the-code-but-skipped-files)。

<Note>
  在 v2.1.216 之前，`/rewind` 会通过已跟踪路径上的链接执行写入和删除，且不会发出警告。
</Note>

### 不能替代版本控制

检查点专为快速的会话级恢复而设计。对于永久版本历史记录与协作：

* 继续使用版本控制（例如 Git）处理提交、分支和长期历史记录
* 检查点是版本控制的补充，而不是替代品
* 可以把检查点理解为“本地撤销”，把 Git 理解为“永久历史记录”
