# Codex 安全插件更新日志

> 有关完整的文档索引，请参见 [llms.txt](https://learn.chatgpt.com/llms.txt)。可以通过在页面 URL 后附加 `.md` 来获取文档页面的 Markdown 版本。

使用此更新日志查看 Codex 安全中的变更以及哪些插件
版本可从每个安装源获取。

**托管 Codex 安全目录中的最新版本：** `0.1.12`。

**公共 Codex CLI 插件市场中的最新版本：** `0.1.11`。

在使用较新版本中的功能之前，请检查当前 Codex 环境中的
插件版本。重新打开或重新运行已保存的扫描不会锁定
已安装的插件版本。

这些版本适用于 Codex 安全插件。Codex 应用、Codex CLI、
TypeScript SDK 和插件应用具有单独的版本号。

## 0.1.12（2026 年 7 月 23 日）

### 以更清晰的进度运行更深入的扫描

- 运行在整个存储库或
  选定目录内协调工作器的深度扫描。
- 将您的模型和推理设置带入委托的扫描工作中。
- 在扫描之前和期间，查看预检结果、扫描进度、可用工作器容量以及回退
  行为。

### 审查并重新运行以前的扫描

- 从安全扫描列表中打开当前和以前的扫描。
- 在发现工作区中重新打开已保存的扫描，或重新运行它以刷新
  结果。
- 查看更清晰的完成状态，以及更一致的发现详情和扫描
  历史。

### 以更少的干扰配置扫描

- 从原生设置流程启动扫描，无需离开您当前的任务。
- 将扫描设置保留在侧面板中，即使 Codex 处于全屏模式。
- 在您不需要时关闭设置，并为以后的
  扫描保留该首选项。

### 审查并修复已验证的发现

- 将已验证的低严重性发现保留在已完成的结果中。
- 在扫描、报告和导出中审查更一致的发现详情。
- 重试修复，并将相关的扫描上下文带入后续修复中。

### 为现有的安全工作流导出结果

- 将已完成的发现导出为 JSON、CSV 或 SARIF。
- 在本地生成 SARIF 结果，用于代码扫描和安全工具
  集成。
- 在各种导出格式中保留一致的发现详情。

## 0.1.11（2026 年 7 月 10 日）

### 生成详细的发现和强化报告

- 为每个可报告的扫描发现生成一份有源代码支持的漏洞报告，
  并在可用时提供支持性的概念验证文件。
- 审查分析完整发现集的结构强化组合，
  包括工程权衡、迁移选项和支持性图表。
- 使用 `report.md` 作为这些派生输出在 `findings/`
  和 `hardening/` 下的入口点。在共享或
  归档结果时，请将完整的扫描目录保留在一起。

### 直接运行报告工作流

- 使用 `$codex-security:vulnerability-writeup` 将披露文档、
  粗略的发现、PoC 和源代码转换为完善的报告，而无需先
  运行 Codex 安全扫描。
- 使用 `$codex-security:propose-security-hardening` 开发有证据支持的
  结构或架构选项，这些选项基于扫描、发现、事件或
  评估文档以及源代码。

### 一致地应用存储库指导和覆盖范围

- 在根目录或嵌套的 `SECURITY.md`
  文件中定义威胁模型上下文、安全不变量、可报告发现
  标准、排除项和严重性上下文。最近的适用文件优先。
- 在验证之前改进存储库审查覆盖率，同时保留
  显式延迟的界面和证明漏洞。
- 在变更扫描中审查已删除的源文件，并在验证之前扩展默认的存储库
  审查覆盖率。
- 在深度扫描开始之前，检查深度扫描阶段技能、委托工作器和工作器
  容量。

## 0.1.10（2026 年 6 月 23 日）

### 改进 Jira 和 Linear 的工单导入

- 在导入 Linear 子工单前进行询问，并在结果中保留父子
  关系。
- 区分连接缺失、权限不足、无法访问的
  工单，以及临时的连接器故障。
- 当请求的工单内容不可用时，停止运行而不是
  创建判定结果。
- 在每个已确认的或需要审查的队列中，从 `1` 开始分配唯一的正整数
  排名。

### 更可靠地审查代码变更

- 将检查的提交与其实际父提交进行比较，并保留差异
  目标到发现工作区中。
- 报告不可用的补丁状态，而不是审查其他变更。
- 审查更加一致的分类结果和发现上下文。

## 0.1.9 (2026年6月18日)

### 在发现工作区中审查扫描

- 在专用工作区中审查已完成的扫描，该工作区将发现、
  覆盖率、严重性、置信度和扫描工件汇集在一起。
- 过滤和排序发现，包括按最高置信度排序，同时
  在刷新时保持您的工作区状态。
- 打开发现以在同一位置审查源证据、验证详细信息、可达性、
  影响和修复指南。

### 以更少的设置运行扫描

- 对 Git 仓库、单个文件夹或
  没有 Git 历史的代码库运行标准扫描。深度扫描也可以针对特定文件夹。
- 显式取消正在进行的扫描，无需再次
  进行设置提示即可恢复中断的扫描，并在启动并发深度扫描之前收到警告。
- 遵循更清晰的设置和进度状态，提供更紧凑的进度
  摘要，并且错误将保持可见，直到您处理它们。

### 导出可移植、可验证的结果

- 使用一致的已完成扫描格式，包含清单、结构化发现、
  覆盖率数据，以及从相同规范结果派生的 Markdown 报告。
- 将发现导出为 JSON、CSV 或 SARIF，用于分析、归档和与其他
  安全工具集成。
- 更可靠地完成扫描，包括在 Windows 路径或扫描锁定
  影响文件系统访问时。

### 分类和跟踪现有的发现

- 针对当前代码库，对来自扫描器、安全公告、漏洞赏金报告、
  GitHub、Jira、Linear 或 Codex Security 结果的现有发现进行分类。
  分类工作流返回有证据支持的判定结果和优先级
  操作队列。
- 在 Linear、Jira 或 GitHub 问题中跟踪选定的已验证发现，或者当仓库满足
  公告要求时，创建一个
  私有的 GitHub 安全公告草稿。
- 在批准写入之前，审查重复检查、源上下文、目标可见性以及
  确切建议的内容。Codex 在创建或更新后回读结果
  以进行验证。

## 0.1.7 (2026年6月4日)

### 运行有证据支持的安全审查

- 扫描授权的仓库或选定的文件夹以查找安全
  漏洞。
- 当您需要更彻底的覆盖时，在整个仓库中运行重复的
  发现。
- 审查拉取请求、提交、分支差异和本地补丁，以检查
  安全回归。
- 在生成扫描报告之前，将每个候选对象通过威胁建模、发现、验证
  和影响分析进行处理。
- 使用集中的补丁、回归覆盖以及对原始问题的
  验证来修复一个已接受的发现。
